# Spec Delta

## Purpose

为订阅方案、链接、超额和已订阅账号提供一致的选择与批量操作界面，帮助用户辨认目标集合、执行进度和失败结果；布局与按钮分组调整继续保持原有计费操作、确认节点及账号关联，不新增支付步骤。

## ADDED Requirements

### Requirement: 三类订阅工作流保持

订阅界面 SHALL 保留超额、链接和订阅管理三个 Tab、方案加载、可升级账号筛选、预检与既有页内状态，不减少原参数、并发设置或条件显示。

#### Scenario: 方案预检与切换 Tab
- **WHEN** 用户加载方案、查看预检后切换到其他订阅 Tab 再返回
- **THEN** 原目标账号与方案规则保持，状态按原页面生命周期恢复

### Requirement: 链接选择和管理等价

订阅界面 SHALL 保留链接获取／导入、全选／反选／清空／按状态／快捷选取、复制／导出、单个／批量打开、重生成与有效性验证，沿用选中或全部的原目标语义。

#### Scenario: 批量打开选中链接
- **WHEN** 用户选中部分成功链接后执行选中范围的原批量打开
- **THEN** 只打开原规则允许的选中链接，未选中或无效链接不因布局变化被打开

### Requirement: 删除与账号联动保持

订阅界面 SHALL 保留原清理、批量删除、失败删除及可选同时删除账号的操作，保留确认和取消结果，不能将清理链接扩大为默认删除账号。

#### Scenario: 不联动删除账号
- **WHEN** 用户按原选项删除链接但未启用同时删除账号
- **THEN** 仅删除原目标链接，账号保留；取消原确认时均不删除

### Requirement: 超额与管理门户保持

订阅界面 SHALL 保留批量超额启停、原账号筛选、已订阅账号管理、单个／批量门户打开和批量关闭超额；原确认、请求参数、任务进度、成功与失败结果保持。

#### Scenario: 取消超额变更
- **WHEN** 用户在原需确认的超额变更中选择取消
- **THEN** 不提交变更；确认后仅处理原目标集合，结果与任务中心同步
