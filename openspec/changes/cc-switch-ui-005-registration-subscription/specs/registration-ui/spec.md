# Spec Delta

## Purpose

以统一的配置、控制和结果层级组织注册界面，让用户继续使用全部邮箱来源、手动步骤和批量调度能力，并能查看失败诊断、重试与历史结果；界面重排不改变注册执行、自动导入、配额或定时逻辑。

## ADDED Requirements

### Requirement: 注册模式与参数完整

注册界面 SHALL 保留 manual、outlook、tempmail、proton、gptmail、mixed 六种模式及各自全部原参数、验证和默认值，混合来源启用与权重继续生效。

#### Scenario: 切换六种注册模式
- **WHEN** 用户分别选择各注册模式并加载已有配置
- **THEN** 对应原字段、凭据、代理及高级选项仍可访问，值和验证规则保持

### Requirement: 手动阶段与结果导入保持

注册界面 SHALL 保留初始化、邮箱、OTP、注册、结果、导入和获取订阅链接等既有阶段及取消；视觉步骤指示不能新增、跳过或自动提交业务阶段。

#### Scenario: 等待用户输入 OTP
- **WHEN** 注册流程进入原等待 OTP 阶段
- **THEN** 用户继续使用原输入／提交／取消操作，未输入时不因界面变化自动推进

### Requirement: 批量调度与控制保持

注册界面 SHALL 保留数量、间隔、并发、重试、自动导入／链接、速率／burst／退避、代理 session 与风控暂停，保持停止／暂停／恢复和任务中心状态的原含义。

#### Scenario: 暂停后停止批次
- **WHEN** 用户暂停批次后执行原停止操作
- **THEN** 按原规则解除暂停并中止相应请求，不残留等待；进度与任务中心沿原结果更新

### Requirement: 自动化与配置兼容

注册界面 SHALL 保留模板保存加载／导入导出、邮箱黑名单／预校验／变体、每日配额、定时与星期掩码，以及既有配置键、触发和恢复范围。

#### Scenario: 不符合星期条件的定时
- **WHEN** 原定时条件达到但星期掩码不允许执行
- **THEN** 按原规则不启动批次，改版不重置配额或自动化配置

### Requirement: 进度诊断历史与跨页结果保持

注册界面 SHALL 保留步骤／耗时／进度、日志、结果、失败诊断和原分类重试、历史重导入、CSV 与分析报表；成功结果继续按原选项进入账号和订阅链接列表。

#### Scenario: 按失败类别重试并返回订阅页
- **WHEN** 用户从失败队列选择原支持类别重试，且成功后启用原链接获取
- **THEN** 仅重试原匹配集合，账号／链接按原规则写入，切页后仍能看到既有结果
