# Design

## Context

RegisterPage 是大型混合组件，含六种 RegMode、手动 Phase、批次模块状态、重试分类、调度与 localStorage。SubscriptionPage 使用模块状态保留页面往返数据，且向注册页导出链接写入方法；三 Tab 为 overage／links／manage。改变组件挂载、回调或这些状态的所有权容易改变任务行为，因此需明确边界。

依赖 001 和 002，复用 TaskCenter 既有契约；003 的账号订阅入口不在本成员重写。功能基线 R01～R05、S01～S04。

## Goals / Non-Goals

**Goals:** 改善配置与运行结果的可辨性，保证大批量任务操作和全部高级选项可达。

**Non-Goals:** 不改变注册策略、预校验／风控、计费／订阅行为、调度器、内存恢复范围或持久化策略，不新增跨进程任务恢复。

## Decisions

1. **沿用现有模式与 Tab。** 注册模式使用统一选择控件，对应字段按来源分区；订阅继续三 Tab，以公共 36px 分段控件呈现。注册六模式同样复用该控件；页头、字体、间距与圆角以 001 ui-contract.md 和 002 PageHeader 为准。没有必要为外观引入新路由、额外向导步骤或调整默认 Tab。
2. **配置、运行控制与结果分层。** 注册保持配置／高级选项区、运行控制和进度、结果日志／重试／历史分析区；高级配置可沿原折叠方式组织，所有旧字段保持。运行时原先不可编辑的字段保持禁用；不将原可用字段全部锁定。
3. **纯呈现拆分保持状态位置。** 如需拆组件，只传值与原回调；模块变量、refs、effect、限速器、时间／配额计算和 appendSubscriptionLink／updateSubscriptionLink 不迁移。避免将模式切换变为销毁并重建任务实例。
4. **批量操作显示原目标集合。** 在现有选择计数旁组织批量工具和运行状态；启停超额、同时删账号、批量门户等动作继续走原确认。表格可滚动，长链接通过原复制操作取得完整值；不改变 quick-pick、selected／all 等规则。
5. **日志和报表保留信息含义。** 使用公共字体、状态和面板；去装饰不移除步骤耗时、错误诊断、分类重试、CSV 或统计。只在显示层改样式，不改计数、过滤与汇总。

## Risks / Trade-offs

- [关闭分区造成任务控件卸载] → 保留原任务状态和订阅生命周期，切页／折叠只按既有机制处理。
- [停止、取消弹窗和取消任务混为一谈] → 三者继续连接原处理器，分别验收暂停后停止、关闭弹窗和重试。
- [表单改造重置模板值或自动化参数] → 固定键值与默认值对比，覆盖星期掩码、每日计数、burst、退避和混合权重。
- [链接清理误删账号] → 联动开关与原确认明确可见，固定样例比较目标账号集合。

## Migration Plan

先改注册配置与手动阶段，再改批量控制和结果，最后逐个订阅 Tab。每一块即时记录功能与截图；外部服务用可控响应核对流程，再在测试环境验证真实路径。无数据迁移，回退呈现提交即可。

## Implementation Notes

本次仅改两页呈现，全部模块状态、refs、调度、存储键与业务过滤保留原位置。订阅管理 50 行虚拟化阈值及 overscan 不变；为保持统一表格单元格内距，行与估算同为 47px，strict containment 的大列表使用明确 60vh 视口。模板文件导入原异步读取完成后清空文件框的动作仍保留，以稳定的 event.target 代替已清空的 event.currentTarget，避免界面异常；文件解析、ID 去重顺序与字段集合不变。二者均由改前复现和改后运行验证单列记录，不修改注册策略或计费业务。
