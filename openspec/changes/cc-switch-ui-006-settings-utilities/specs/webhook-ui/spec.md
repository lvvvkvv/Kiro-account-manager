# Spec Delta

## Purpose

为通知渠道和订阅事件提供统一的配置与状态界面，使用户继续管理现有 Webhook、测试连接并辨认启停和失败结果；界面整理不会改变事件集合、发送参数、调用时机或现有通知服务的行为。

## ADDED Requirements

### Requirement: 渠道与事件配置保持

Webhook 界面 SHALL 保留钉钉、企业微信、Telegram、Discord、飞书、自定义六类渠道及七类原事件，保留各字段、验证、启停、编辑和删除操作。

#### Scenario: 编辑并取消渠道配置
- **WHEN** 用户选择任一原渠道和事件后取消编辑
- **THEN** 原配置保持；保存时沿原字段及验证写入，不丢失已有事件选择

### Requirement: 测试与反馈保持

Webhook 界面 SHALL 保留原测试入口、处理中禁用与结果反馈；页面打开、切换、折叠或样式变化不能额外触发测试或发送通知。

#### Scenario: 明确发起测试
- **WHEN** 用户点击某条目原测试操作
- **THEN** 只按原流程测试该条目并显示结果，未点击的条目不因新布局发送消息
