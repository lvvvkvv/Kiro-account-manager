# Spec Delta

## Purpose

提供分组清晰且风格统一的应用设置界面，使用户继续访问现有外观、账号自动化、网络、托盘、快捷键和数据选项；整理表单与操作反馈时保持每项设置的验证、生效方式和既有持久化兼容。

## ADDED Requirements

### Requirement: 全部设置可达

设置页 SHALL 保留001 定义的跟随系统／浅色／深色、中文／英文、账号隐私遮罩／精度／私密登录，以及自动刷新／主动续期、API 类型／KProxy／代理、自动切换、导入并发、切换目标、托盘、快捷键和数据操作。

#### Scenario: 访问高级与数据设置
- **WHEN** 用户在设置页按新分组访问任一原选项
- **THEN** 原字段、范围、说明和操作仍可找到，没有以简化布局为由隐藏或删除功能

### Requirement: 验证生效与偏好兼容

设置页 SHALL 保留各选项原默认值、即时或显式应用时机、验证和存储键，加载旧配置不重置；账号导出继续使用原输出规则，清理操作保留原确认。

#### Scenario: 旧偏好与代理显式应用
- **WHEN** 用户加载旧偏好并修改原需显式应用的代理地址
- **THEN** 旧值正常显示，新值按原应用条件提交，不因统一表单而自动生效；重启回读沿用原持久化

### Requirement: 内嵌配置同步独立兼容

设置页 SHALL 保留内嵌配置同步的 JSON 格式标识、对象形式代理池、原 ID、偏好键集合、覆盖确认和重启提示；不能以独立同步页的格式、合并或加密流程替代。

#### Scenario: 导入内嵌同步文件并取消覆盖
- **WHEN** 用户从设置页内嵌同步入口导入原支持的 JSON 文件并取消覆盖确认
- **THEN** 不恢复偏好或覆盖代理池；确认时按原格式、键集合和 ID 恢复，不改为独立同步页的追加行为
