# Design

## Context

八页分别拥有领域状态与系统／网络动作。SettingsPage 既有即时保存也有本地编辑后显式应用；机器码依赖权限及文件 API；Kiro 设置有 MCP／Steering 独立编辑器；诊断可更新或删除账号；ConfigSync 只同步明确字段集合；LogsPage 每 1500ms 拉取并维护底部跟随。统一外观不能抹平这些差异，因此分别建立八项 UI 契约。

依赖 001 公共视觉和 002 PageHeader。003 的 ExportDialog 以原接口复用，没有新的硬依赖；串行计划下 003 会先完成。功能基线 U01～U10。

## Goals / Non-Goals

**Goals:** 完成剩余八页及内嵌编辑器的一致性，用原回调保留全部设置与工具操作。

**Non-Goals:** 不添加设置目录路由、搜索、密度选项、配置同步字段或新编辑器框架；不改变系统操作、发送机制、诊断算法或日志服务。

## Decisions

1. **页面保持独立，套用共同页头。** 用字段分组、分隔线和中性面板组织信息；不照搬 CC Switch 设置页切换整个侧栏目录的导航，因为本项目没有相同子路由。各页保留原滚动与折叠状态所有权。
2. **设置按外观／账号自动化／网络／系统与托盘／数据分区。** 依照用户实施阶段的最新决定引用 001：外观仅跟随系统／浅色／深色，固定橙色；语言仅中文／英文，保留账号信息遮罩。即时选项仍即时，需显式应用的代理字段保留应用动作；本成员不再恢复多色主题或自动语言。
3. **机器码和 Kiro 编辑保持领域边界。** 系统状态、设备操作、账号绑定、历史各成组；MCP／Steering 弹窗使用公共外观，但原输入和保存／取消处理器不动。配置文件写入仍通过既有 API。
4. **运维操作区分查看与副作用。** Webhook 条目与编辑表单保留测试按钮的明确触发；诊断分网络检查和账号存活区，复测／标错／删除按原选择与确认；不要把进入页面和执行操作合并。
5. **两条配置同步路径分别保留。** 独立页保留 PortableConfig、REGISTER_LS_KEYS、脱敏、KCFG1／.kcfg、加解密与合并；设置内嵌 ConfigSyncCard 保留 type 标识、对象代理池／原 ID、COLLECTED_LS_KEYS、覆盖确认和重启提示，不合并格式或承诺原本不存在的脱敏／加密。现有重置只移除实现列出的键，即使文案比实际集合更宽，也不扩展范围。密码输入若换视觉容器，保持原取消／失败行为。
6. **日志和关于内容保留。** 日志工具区和密集正文共用 Token，滚动容器 ref 与轮询不搬迁，导出仍以原过滤集合生成。关于页只改标题、信息与弹窗外观；不重写更新查询，不覆盖 002 的全局 UpdateDialog。

## Risks / Trade-offs

- [统一保存按钮改变即时配置] → 逐字段登记原应用方式，沿用回调，不建立新的全页草稿状态。
- [配置同步被误认为涵盖所有新 UI 设置] → 只比较现有实际字段，不新增周掩码等目前未导出的键，缺口另记。
- [日志滚动容器替换改变跟随] → 保留 ref 与滚动处理，验证离底部阅读和新增提示。
- [操作外观弱化危险动作] → 机器码恢复、账号删除、数据清理等沿用危险语义与原确认；不为统一模态擅自新增或去掉确认。
- [八页范围较大] → 按页面小任务实施并即时记录验证，不等全部迁完再统一发现领域回归。

## Migration Plan

按设置、机器码、Kiro、Webhook、诊断、配置同步、日志、关于的顺序逐页改呈现，每页完成即核对 U 项。没有数据迁移；回退页面呈现提交即可。全部成员完成后按总计划检查 15 页、共享弹窗和跨领域入口。
