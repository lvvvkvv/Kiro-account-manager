# Spec Delta

## Purpose

为代理池提供清晰的条目、调度和账号绑定交互，让用户继续导入维护代理、检查可用性与代理链，并管理账号分配；统一页面密度和批量工具时保持协议支持、目标集合、策略参数和关联结果兼容。

## ADDED Requirements

### Requirement: 条目与批量操作兼容

代理池 SHALL 保留单条／批量导入、全部原支持协议与凭据语法、标签编辑、复制、启停、删除、移除失效、文本和高级筛选，以及单条／选中／全量验活的原范围。

#### Scenario: 高级筛选后验活选中项
- **WHEN** 用户用原输入格式导入代理、应用高级筛选并验活选中项
- **THEN** 解析结果、可见集合、验活目标与汇总等价，未选中代理不被误处理

### Requirement: 策略与链路配置保持

代理池 SHALL 保留原调度策略、严格代理、失败停用、定时刷新、上游链配置和链路诊断，沿用验证、配置存储和即时／后续应用规则。

#### Scenario: 严格代理无可用条目
- **WHEN** 用户保持严格代理配置并在无可用代理时执行原相关操作
- **THEN** 展示原状态与处理结果，界面改版不能放宽直连规则或改变回退策略

### Requirement: 账号分配与解绑保持

代理池 SHALL 保留账号 N:1 绑定、分配未绑定／重新分配、单项／全部解绑及原确认，继续与账号页共享结果和删除代理时的联动规则。

#### Scenario: 取消全部解绑
- **WHEN** 用户发起全部解绑但取消原确认
- **THEN** 原绑定保持；确认解绑后的账号页与代理池显示相同结果
