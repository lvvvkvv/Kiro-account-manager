# Spec Delta

## Purpose

为 API 反代提供一致的服务控制和配置界面，使用户继续管理监听、账号、模型、客户端接入、密钥、安全与日志，并清楚识别运行和变更状态；交互重排保持协议参数、应用时机和服务结果完全兼容。

## ADDED Requirements

### Requirement: 服务控制与配置应用等价

反代界面 SHALL 保留启停、状态、监听地址／端口、API Key、自启动及原配置生效规则，继续区分即时生效和需要重启的变更，不能新增自动重启或改变原重启时机。

#### Scenario: 运行中修改配置
- **WHEN** 用户在运行中修改原支持的监听或高级配置
- **THEN** 使用原参数及应用方式，既有重启提示与处理保留，状态和错误可见

### Requirement: 账号模型与接入能力保持

反代界面 SHALL 保留单／多账号与分组选择、调度／耗尽切换、账号同步、模型查询刷新／映射、客户端配置生成与复制及全部原请求／工具／Agent 设置。

#### Scenario: 选择账号与模型映射
- **WHEN** 用户调整账号集合、映射后生成原支持的客户端配置
- **THEN** 目标集合、映射内容与配置输出语义相同，原高级设置仍可访问

### Requirement: 密钥与安全管理保持

反代界面 SHALL 保留 API Key 格式、名称、启停、额度、显示复制、删除和用量，及 IP 规则、外部访问、限流、会话亲和、超时、回退端口、指标、TLS／自签证书和审计等原安全操作。

#### Scenario: 证书重生成取消与密钥用量
- **WHEN** 用户取消原证书重生成确认，随后查看某 API Key 用量
- **THEN** 不重生成证书，原密钥统计仍正确显示，安全设置的验证与生效时机不变

### Requirement: 日志与统计操作保持

反代界面 SHALL 保留请求／详细日志的记录、过滤、明细、复制、清理和保存配置，以及现有请求／积分／Token 等统计与各自重置范围。

#### Scenario: 清理日志与重置统计
- **WHEN** 用户分别使用原清理日志和统计重置操作
- **THEN** 各操作只影响原本对应数据范围，展示结果和确认流程保持，不能合并成全量清空
