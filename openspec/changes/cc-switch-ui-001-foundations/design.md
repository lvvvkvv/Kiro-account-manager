# Design

## Context

动机见 proposal.md。`main.tsx` 实际引入 `styles/globals.css`，`assets/main.css` 是未接入的模板样式。现有全局 CSS 定义 glass、gradient、ambient、active-glow 等效果，Button／Card 及领域页面同时使用它们和局部 class／style。跨模块影响符合本变更编写设计的条件。

参考固定到 CC Switch 提交 `f29d0804b05ce374ee650c64706399cd0da01805` 的 `src/index.css`、`tailwind.config.cjs`、`docs/design-system.html` 与 UI 控件。目标是样式和交互约定，本项目继续使用 Tailwind 4 的 `@theme`。

## Goals / Non-Goals

**Goals:** 形成一套兼容旧调用方的公共 Token 和呈现基础，供 002～006 使用。

**Non-Goals:** 不替换 Electron、状态管理、依赖体系或持久化字段结构；不新增界面密度选项；不实现领域弹窗内容与业务动作。

## Decisions

1. **在现有 CSS 入口内映射语义 Token。** 浅色应用／侧栏／卡片使用 `#FFFFFF / #F5F5F7 / #FFFFFF`，深色 `#1C1C1E / #161618 / #2E2E33`；主／次／辅助文字分别取参考项目三级值，边框使用中性弱／强两档。操作色、链接色、hover 和 soft 底色分开，不把旧 `primary` 的所有使用机械替换为橙色。直接复制对方 Tailwind 3 配置会产生不兼容，因此只迁移值与角色。
2. **保留旧属性和变体，映射新外观。** Button 的 default／gradient 映射主操作，outline 映射中性描边，ghost／secondary 映射透明／低强调，destructive 保留危险语义；Card 的 glass 系列继续可调用但渲染实色。必要的新变体保持局部、兼容，不为本轮创建通用业务框架。
3. **按用户 2026-11-26 最新决定简化设置。** 外观与 CC Switch 一致，仅跟随系统／浅色／深色三档，固定橙色操作强调；删除 32 色选择器及其全部 CSS。新配置默认跟随系统，旧颜色键按跟随系统解析；保留现有 theme／darkMode 字段承载选择与生效状态，不新增存储键。语言仅中文／英文，旧 auto 或无效值在加载时解析为系统对应的中文或英文。账号信息遮罩功能保留，只统一外观；不加入请求正文脱敏。系统颜色变化仅在跟随系统时生效，监听在卸载时清理。
4. **公共样式只决定外观。** 弹层／菜单使用 14px／10px 圆角及统一遮罩、边框和内边距；关闭策略、键盘规则、值提交与触发回调由领域调用方保留。可复用轻量呈现结构，不强制将所有手写弹窗迁入新库。
5. **领域硬编码由其所属成员清理。** 001 提供公共尺寸与 Token；002～006 分别清理各自 hero、渐变、内联背景和过小字号。避免用全局 `!important`、通配选择器或覆盖全部颜色来强制迁移，否则会破坏状态与图表含义。

6. **全部公共 UI 细节共享同一套约定。** 按用户补充要求，字体栈、字号／行高／字重、间距、圆角与尺寸均逐项参照固定版本。除现有组件外，还提供导航、页头、工具栏、分节／设置行、分段、页签、表格、提示、通知条和 Toast 的纯呈现 CSS 入口，定义见 ui-contract.md。002～006 迁移领域页面时直接消费；不在 001 建立新的导航、通知或弹窗业务系统。

## Risks / Trade-offs

- [共享样式先变化，局部页面暂未迁移] → 保持原接口和兼容类；001 在代表页面确认可用，各领域完成后再整体验收。
- [橙色链接与操作色角色混淆] → 与 CC Switch 一致：操作背景用橙色白字，链接使用深一档文字色；前景、背景、链接分别映射。
- [发光边框同时承载当前账号／标签信息] → 外观可移除，状态文字、徽标、标签颜色与选择结果必须保留；具体替换由 003 完成。
- [默认控件变紧凑] → 只约束单行基础控件，允许多行、长文本和编辑器扩展，最小窗口检查溢出。

## Migration Plan

先映射 Token，再调整基础控件，保持旧变体直到全部领域调用迁移完成。不清空用户数据；仅按上述规则解析废弃的外观和语言值。出现样式回归时回退对应 CSS／控件提交，不清空用户偏好；001 未稳定前不实施依赖成员。
