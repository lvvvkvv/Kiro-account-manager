# Design

## Context

AccountManager 同时管理导入解析和弹窗显隐，Toolbar 管理搜索、分组、批量集合与代理绑定。AccountCard 和 AccountListRow 各有业务动作；AccountList 虚拟行高 72px、间距 10px，AccountGrid 按 340px 高度虚拟化且通过 ResizeObserver 计算列数与卡片宽。AddAccountDialog 含多种异步登录和凭据验证，不能将布局拆分演变为业务重写。

依赖 001 的 ui-foundations、002 的 PageHeader；规范与设计按前置规划承接，不复制各自主题或框架。功能基线 A01～A07。

## Goals / Non-Goals

**Goals:** 在可控的呈现调整中统一高密度账号交互，保持虚拟滚动、登录回调和全部操作能力。

**Non-Goals:** 不合并两套账号动作逻辑、不改导入解析、登录协议、store 或存储，不为视觉改版修复既有业务差异。

## Decisions

1. **采用标题＋工具区＋内容区。** PageHeader 主按钮为添加账号；导入／导出和管理类操作使用中性操作，可将次要管理项分组到菜单。分组 Tab、搜索筛选和视图切换独立一行，选中后展示批量工具区；沿用原选中集合、全选范围和筛选值，不创建新的派生业务状态。
2. **卡片和列表共享视觉语言，不强行统一处理器。** 顶部身份／状态，中段用量／期限／标签与代理，底部原操作。当前账号采用清晰边框＋当前徽标；标签渐变光环改为原颜色标签，封禁保持文字和危险语义。两种视图原有能力分别核对，不凭设计图推断行为相同。
3. **保留网格与列表虚拟化布局约束。** 默认沿用现有高度及两个虚拟器，网格保留随容器调整列数；内部字体和操作按新规范排列。若实测内容需要改高度，必须同步 estimateSize 与实际高度并验证滚动定位；不移除虚拟化，不将 CSS 自动换行套到固定高度外容器。
4. **领域弹窗保持原业务边界。** 登录模式与 provider 使用分段／选择控件，输入、区域、私密选项、进度和结果按现有阶段组织；登录取消调用原处理器。普通详情／编辑／分组／标签／导出使用统一标题、滚动正文、操作区，字段、关闭条件、确认节点与剪贴板输出不变。
5. **跨领域只保留现有调用。** 本成员独占 ExportDialog 外观，SettingsPage 的调用签名不变；代理绑定仍走 accounts store，订阅入口沿用原账号字段和 API。004、005 没有新接口前置需求。

## Risks / Trade-offs

- [卡片子操作冒泡改变选择] → 保留现有 stopPropagation／事件边界，以选择＋操作组合验证。
- [页面密度变化破坏虚拟滚动] → 固定高度与估值一起核对，测试多账号、长邮箱和列表末尾添加入口。
- [弹窗重排卸载登录子树] → 保持现有状态所有权和 effect 依赖；取消、回调成功、失败后重试逐路径比对。
- [菜单收纳导致批量目标不清楚] → 批量区保留选中数及动作名称，未选中状态仍按原规则，不新增默认全量目标。

## Migration Plan

先迁移标题工具区，再改卡片列表，最后逐个迁移账号弹窗。每一步带同范围功能记录和截图；无需数据迁移。回退对应呈现提交即可；保持全部原调用签名避免阻塞 006。

## 实施落点

按决策 3 的实测调整：统一字号后卡片行槽 420／实体 404，间距 16，同步虚拟器估值与末尾添加项；内部配额保留滚动。列表继续 72 实体／82 估值，使用 1480 最小内容宽（审查时对齐 8px 操作间距后同步调整）和外层横向滚动保留全部列及操作，窄窗口不隐藏时间与操作。详情／方案沿原 672 内容宽，其他弹窗使用默认 512。尺寸与功能证据见 implementation.md。
